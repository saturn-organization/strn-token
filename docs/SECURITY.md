# STRN security model and audit review map

This page describes STRN. See [SSTRN_SECURITY.md](SSTRN_SECURITY.md) for the companion staking contract and its cross-contract boundaries.

Production token scope is `src/STRN.sol` plus pinned OpenZeppelin parents and TransparentUpgradeableProxy/ProxyAdmin. `script/DeploySTRN.s.sol` is the offline deployment recipe; `script/BuildSTRNRoles.s.sol` builds unsent initial role grants. Test staking and upgrade fixtures are not production components. No onchain deployment has occurred.

## Review scope

Traced ordinary transfers through inherited allowance spending and `_update`; approval uses the unmodified parent. Seizure calls the ERC20 parent directly only after authorization, protected-source, blacklist, amount and recovery validation. Recovery configuration and custody registration cannot make the recovery address protected. Custom state uses the STRN ERC-7201 namespace, including blacklist, recipient, custody, restricted balances and recovery checkpoints. Namespace slots and preservation across a compatible upgrade are tested.

The deployment-only primitive checks five-day delay and code presence. The complete `runWithRoles` path and standalone role builder additionally check chain ID, the selected proposer/canceller, open execution and token role administration. These do not attest authentic bytecode, complete membership, existing grants, signer security or upgrade safety. Generated grants are additive, not a replacement of other holders. Production configuration must keep custody registration and recovery-address authority under reviewed governance; assigning PARAMETER_MANAGER_ROLE to the timelock makes destination changes delayed. Emergency pausing can use a narrower operator. Token default-admin handoff delay is distinct from timelock operation delay.

## Remaining launch parameters

Confirm branding/decimals, initial allocation recipient, recovery recipient, role memberships, authentic timelock address and proposer/canceller/executor arrangement, admin-transfer delay, custody registrations, and upgrade/decommission procedures. The [Ethereum manifest](../config/README.md) records public governance candidates and their historical provenance; operational deployment inputs and approvals remain incomplete. Verify current state before deployment.

Obtain independent audit and review exact source/compiler/dependency hashes and atomic initialization calldata before a separately authorized deployment. No legal clearance, exchange acceptance, governance adoption or live utility is established here. The companion sSTRN contract is specified in [SSTRN_SPEC.md](SSTRN_SPEC.md); synthetic integration fixtures remain test-only. Reward distribution and product fee economics are external integration responsibilities.

Liquid voting: seizure records a locked, non-voting balance in the recipient wallet; normal transfers cannot consume it. Explicit RELEASER_ROLE release restores eligible liquid units without changing supply. Rotation leaves previous locks intact. Custody registration removes its outgoing votes; backing cannot delegate, while other holders may independently delegate to the custody address. Historical snapshots are never rewritten by blacklist or recovery. Review EIP712/nonces, combined vote conservation and recovery checkpoints. This is an initial-deployment extension, not a live vote-history migration.

Fresh liquid-voting static analysis reports one medium unused-return warning for Checkpoints.push: its return values are old/new checkpoint values, not a success flag; the call persists or reverts. Historical recovery tests and stateful time advancement cover the recorded values. Two low calls-loop findings refer to the bounded six-role read-only deployment builder. The informational dead-code report for \_getVotingUnits is a virtual-dispatch false positive: inherited Votes.\_delegate calls the STRN override, and mixed recovered/ordinary balance delegation tests require that override. Informational assembly and CLOCK_MODE naming are intentional namespace/standard-interface constructs. Preserve raw findings and re-review future changes; these explanations are not detector suppressions.
